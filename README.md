# SalesInsight — E-commerce Sales Analytics

An end-to-end data analyst project: a reproducible synthetic sales dataset,
12 business questions answered in SQL, a pandas + SQLite analysis pipeline
that exports report tables, and an interactive Streamlit dashboard.

Built to demonstrate the exact day-to-day workflow of a Data Analyst role:
take raw transactional data, clean and structure it, answer business
questions with SQL, summarise with Python, and present KPIs in a dashboard
stakeholders can explore themselves.

## Stack

- **Python** — data generation, pandas for loading/cleaning/analysis
- **SQL (SQLite)** — 12 business queries in `analysis.sql`, including
  `GROUP BY` aggregations and window functions (`LAG()` for growth)
- **Streamlit** — interactive dashboard with filters and KPI cards
- **CSV** — raw data and exported report tables

## Dataset

`sales_data.csv` — 5,000 synthetic e-commerce orders for calendar year 2024,
generated by `generate_data.py` with a fixed seed (42), so the file is fully
reproducible. Columns:

| Column | Meaning |
|---|---|
| `order_id` | Unique order ID (ORD00001…) |
| `date` | Order date, 2024-01-01 to 2024-12-31 |
| `region` | North / South / East / West / Central |
| `category` | Electronics, Fashion, Home & Kitchen, Beauty, Sports, Books |
| `product` | 29 products with realistic per-category price ranges |
| `quantity` | Units in the order |
| `unit_price` | Price per unit |
| `revenue` | quantity × unit_price |
| `customer_id` | One of 1,200 customers (repeat buyers included by design) |

The generator builds in realistic patterns: a festive-season (Oct–Dec)
demand spike, a monsoon dip, regional price differences, and a pool of
repeat customers — which is what makes the analysis findings meaningful
rather than flat random noise.

## Business questions it answers

1. What are the headline KPIs — total revenue, orders, average order value, unique customers?
2. How does revenue trend month by month, and what is the month-over-month growth?
3. Which regions drive revenue, and what share does each contribute?
4. Which categories earn the most, and which have the highest average order value?
5. Which products are the top revenue earners vs the top volume sellers?
6. How much revenue comes from repeat customers vs one-time buyers?
7. Who are the top customers by lifetime spend?
8. How does average order value differ by region?
9. How does each category perform inside each region?
10. Which quarter was strongest?

## How to run

```bash
pip install -r requirements.txt

# 1. Generate the dataset (creates sales_data.csv)
python generate_data.py

# 2. Run the analysis (prints a summary, writes report tables to outputs/)
python analysis.py

# 3. Launch the interactive dashboard
streamlit run app.py
```

`analysis.sql` can also be run directly against any SQLite database that
has the CSV loaded as a table named `sales`.

## Example findings (from the actual generated data)

1. **Electronics is the revenue engine.** It contributes ₹10,416,498 of the
   ₹24,250,360 total revenue — about 43% — from 1,262 orders, with the
   highest average order value of any category (₹8,254). A single product,
   Smart Watch, accounts for ₹3,590,094 (~15% of all revenue).
2. **Sales are strongly seasonal.** October 2024 was the best month at
   ₹2,801,544 revenue, a **+53.8% month-over-month jump**, while July was
   the weakest at ₹1,594,946 — peak month revenue is ~76% higher than the
   trough, the classic festive-season pattern for Indian e-commerce.
3. **Repeat customers drive the business.** 932 of the 1,118 customers
   (83%) ordered more than once, and they generated ₹23,413,310 — **96.5%
   of total revenue**. One-time buyers are only 3.5% of revenue, so
   retention matters far more than acquisition for this store. Regionally,
   North leads on revenue share (26.5%) while South has the highest
   average order value (₹5,043).

## Interview questions — with model answers

**1. How did you calculate month-over-month growth in SQL?**
I first aggregated revenue by month with `GROUP BY strftime('%Y-%m', date)`,
then used the `LAG()` window function to bring the previous month's revenue
onto each row. Growth is `(this month − last month) / last month × 100`.
LAG is the right tool because it accesses another row of the result set
without a self-join.

**2. What is the difference between WHERE and HAVING?**
WHERE filters individual rows before grouping; HAVING filters groups after
`GROUP BY` aggregation. If I want only orders above ₹5,000, that's WHERE.
If I want only categories whose total revenue exceeds ₹20 lakh, that's
`HAVING SUM(revenue) > 2000000` — the condition is on an aggregate.

**3. How did you clean and prepare the data in pandas?**
I loaded the CSV with `parse_dates` so the date column is a real datetime,
checked for nulls per column with `isna().sum()` (there were none after
generation), verified the date range, and derived a `month` column for
grouping. Then I loaded the frame into SQLite so the exact same data could
be queried in SQL — the point was to show both tools on one dataset rather
than doing everything in one place.

**4. How do you define your KPIs, and why those?**
Total revenue is `SUM(revenue)`; average order value is total revenue
divided by number of orders — here ₹24,250,360 / 5,000 ≈ ₹4,850; repeat
customer rate is the share of customers with more than one order (83%).
I chose these because they separate three different business levers: scale
(revenue/orders), basket size (AOV), and retention (repeat rate) — a change
in revenue can then be explained instead of just reported.

**5. How did you design the dashboard so a non-technical stakeholder can use it?**
KPIs go at the top as five metric cards because that's the first question
("how are we doing?"), the trend chart comes next ("is it getting better?"),
and breakdowns and the top-products table below for detail. Filters for
region, category and date range sit in the sidebar and every chart and
table responds to them, so a stakeholder can answer their own follow-up
questions — e.g., Electronics in the South only — without asking for a new
report.
